## Quick start

Open the calendar: double-click `liquidity-calendar/index.html`, keeping `bills.js`, `ladder.js` and `app.js` beside it. Add payment dates, or choose "Try example dates".

Refresh the data. This needs internet access and writes a candidate, never the accepted files:

```text
python3 extensions/auto-refresh/refresh.py
```

Without internet access, download the files by hand and pass their folder:

```text
python3 extensions/auto-refresh/refresh.py --sources <folder>
```

The folder needs `treasury_<last year>.xml`, `treasury_<this year>.xml` and `cpi_2023_2026.json`; the download URLs are in `../SOURCE_REGISTER.csv`. The CPI file keeps that name, which `rebuild.py` expects, even though it covers 2023 to the current year.

Run the checks (Node 18+ and Python 3.10+):

```text
node extensions/tests/check_extensions.mjs
```

## How the refresh behaves

1. It starts from the accepted snapshots in `../data/raw/`, replaces the two latest Treasury years and the CPI series, then runs the accepted rebuild checks.
2. It stops with exit 1 and writes nothing when:
   - a download fails;
   - a field or unit is wrong;
   - quotes or CPI are older than the accepted release;
   - the bill list disagrees with the dashboard.
3. It uses a new CPI month only after that month's BLS release date in the schedule. Before then it keeps the previous month and prints a WARNING.
4. It marks the data set `refresh.mode: automatic` with a daily cadence, and points the Treasury source link at the year of the latest quote.
5. In the `--out` folder it writes `project.json`, `data/raw/`, the normalized CSVs and `refresh_report.json`, then `data.js` last. It also writes `bills.js` for the calendar.

## Adopting the refresh (a group decision)

The course allows `refresh.mode: "automatic"` only after the group has run and tested `refresh.py` (`../reference/AGENT_GUIDE.md`). To adopt it:

1. Copy `auto-refresh/refresh.py` to the project root. It finds the root by `calculations/rebuild.py` and keeps reading the schedule from `extensions/auto-refresh/`.
2. Run `python3 refresh.py` at the root. It then writes beside itself, as the course specifies: `data.js`, `project.json` and `data/`.
3. Record the decision and the run in `../AI_LOG.md`, `../AGENT_TEST.md` and `../EVALS.md`.
4. Agree who schedules the run (the course lab or another daily job) and who reads its warnings.

A group member's improvement plan asks that no automatic download or background scheduling be added without authorization. The manual mode (`--sources`) meets that rule and keeps the same checks.

## Yearly maintenance

- Each autumn, add the next year's CPI release dates to `auto-refresh/cpi_release_schedule.csv` from https://www.bls.gov/schedule/news_release/cpi.htm.
- If Treasury or BLS change field names or request limits, the refresh stops and names the problem. Fix the input or the script, then rerun the checks.

## Limits

- The calendar compares dates only. It does not judge whether a payment can be met, price a purchase or rank bills.
- Saved quotes are not executable offers. Settlement, receipt of funds, taxes and fees are not assessed.
- The calendar is a separate page; the course dashboard (`../index.html`) is unchanged.
